# POC-2 — إثبات جدوى تكامل YouTube / Creator Studio

> **الهدف:** إثبات أن الربط والقراءة والرفع تُنفَّذ فعليًا ضمن الصلاحيات المعتمدة، وقياس الحصص والقيود بأرقام من بيئة حقيقية — **قبل** أي وعود بميزة نشر أو تحليلات أو وكلاء.
> **الحالة:** مخطط — لم يبدأ.
> **قاعدة الانفصال:** مستقل عن الطبقة الأولى؛ فشله لا يؤخر إطلاق المنصة الأساسية.

---

## 1. الحقائق المؤكَّدة مسبقًا (مصدر: Google — فحص 2026-10-26)

| البند | القيمة | ملاحظة |
| --- | --- | --- |
| تصنيف نطاقات YouTube | **sensitive** (بما فيها للقراءة فقط) | يتطلب مراجعة Google قبل الإطلاق للعامة |
| التطبيق غير المُوثَّق | حتى **100 مستخدم اختباري** يمنحون الإذن، وما عداهم يرى تحذير | كافٍ تمامًا لـ POC |
| مدة المراجعة | sensitive: 3–5 أيام عمل · restricted: 4–6 أسابيع + تقييم أمني سنوي | تؤثر على جدول الإطلاق لا على POC |
| الحصص الافتراضية | 10,000 وحدة/يوم لكل مشروع | **تعارض بين مراجع قديمة وحديثة حول تكلفة `videos.insert` (1,600 وحدة سابقًا مقابل دلو مستقل 100/يوم حاليًا) → نقيس بأنفسنا** |
| رموز OAuth | 100 refresh token لكل عميل ومعرف Google | رموز وضع الاختبار قد تنتهي بعد 7 أيام (يُتحقق وقت التنفيذ) |

**القرار:** كل هذه الأرقام مؤكَّدة من مصادر Google العامة، لكن **الأرقام الخاصة بمشروعنا تُقاس في POC** ولا تُسجَّل كواقع قبل ذلك.

## 2. المتطلبات القانونية والسياسات

| البند | المطلوب | الحالة |
| --- | --- | --- |
| سياسة خصوصية | صفحة توضح ما نقرأه ومتى نحذفه (شرط Google) | مطلوب قبل أي ربط حقيقي |
| شروط YouTube API Services | قراءة كاملة وتوثيق الالتزام | مطلوب |
| ملكية القناة | قناة يملكها فريق التطوير ويصرّح بربطها | شرط POC |
| موافقة المستخدم | موافقة صريحة عند الربط + إمكان إلغاء التفويض | شرط تصميم |
| رموز الوصول | تُخزَّن مشفّرة في مخزن أسرار خادمي، لا تمر بالمتصفح | قرار معماري ثابت |

## 3. إعداد بيئة الاختبار

1. مشروع Google Cloud + تفعيل **YouTube Data API v3**.
2. موافقة OAuth بحالة **Testing** + نطاقات بأقل صلاحية ممكنة:
   - `youtube.readonly` (القراءة)
   - `youtube.upload` (الرفع — فقط إذا اختبارنا الرفع)
3. إضافة مستخدمي الاختبار (فريق العمل) إلى قائمة الاختبار.
4. قناة اختبار يملكها الفريق — **لا قناة عامة أو لحساب طرف ثالث**.
5. توثيق كل إعداد في `docs/poc-youtube-setup.md` (قوالب المفاتيح في `.env.example` فقط، دون قيم).

## 5. بوابة القبول (ترتبط بـ CRE-01..03 وAGT-01)

- [ ] **CRE-01:** ربط قناة يملكها الفريق يعمل، وتُعرض الصلاحيات الممنوحة، وإلغاء التفويض يوقف الوصول.
- [ ] **CRE-02:** البيانات المعروضة = ما تعيده الواجهة الرسمية فقط، مع طابع زمني للتحديث.
- [ ] **CRE-03:** رفع فيديو غير منشور ينجح وتُقرأ حالته من الواجهة الرسمية، والفشل يُظهر سببه.
- [ ] **الحصص:** أرقام استهلاك فعلية مسجّلة (وحدات/يوم لكل نوع عملية).
- [ ] **SEC-01:** لا رمز وصول يظهر في المتصفح أو السجلات؛ اختبار إلغاء التفويض ناجح.
- [ ] **AGT-01:** مهمة منخفضة المخاطر واحدة تُنفَّذ عبر الوكيل مع سجل كامل وموافقة صريحة، ومحاولة تجاوز الصلاحية تُرفض.

## 6. الوكيل (AGT-01) — التصميم قبل أي تنفيذ

| العنصر | القرار |
| --- | --- |
| الأدوات | قائمة مغلقة مُعرَّفة مسبقًا (قراءة بيانات، جدولة/رفع…) — لا أداة عامة |
| الصلاحيات | تُمنح لكل مهمة على حدة، منخفضة المخاطر أولًا |
| الموافقات | عملية حساسة (نشر/تعديل/حذف) تتطلب موافقة مستخدم صريحة قبل التنفيذ |
| السجل | كل تشغيل له: المهمة، الأدوات المُستخدَمة، المدخلات، النتيجة، الحالة، الوقت |
| الفشل | يُعرض للوكيل ويُسجَّل، ولا يُعاد تلقائيًا بلا قرار بشري |
| السقف | عدد عمليات/يوم للوكيل محسوب في الخادم |

**لا يُفعَّل الوكيل في الإنتاج قبل اجتياز كل ما سبق في بيئة الاختبار.**
