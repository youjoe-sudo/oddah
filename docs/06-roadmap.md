# خارطة الطريق بعد التحديث (الإصدار 0.2)

> **الأصل:** القرارات المعتمدة موثّقة في `README.md` (جدول القرارات) وفي `docs/04-content-sources.md` (سجل القرارات D-01..D-06).
> **هذه الوثيقة** تترجمها إلى مسار تنفيذ بمعايير قبول وبوابات قرار.

---

## 1. المبدأ الحاكم

**إطلاق المنصة الإسلامية الأساسية لا يرتبط بأي ميزة تجريبية.**
الصوتيات وCreator Studio يُطَوّران بالتوازي كمسار تحقق، ونتيجتهما تُقرر توسعة النطاق — لا سرعة إطلاق الأساس.

---

## 2. المساران المتوازيان

### المسار A — المنتج الأساسي (شرط الإطلاق)
الهيكل والتصميم ← الحسابات والصلاحيات ← القرآن والعبادات ← المكتبة والبحث ← الإدارة ← اختبار الإطلاق.

### المسار B — إثبات الجدوى التقنية (لا شرط للإطلاق)
تجربة فصل الصوت ومصادره (`02-poc-audio.md`) ← تجربة ربط YouTube والرفع (`03-poc-youtube.md`) ← اختبار المونتاج والمعالجة ← قياس التكلفة والقيود.

### نقطة الدمج
تُوحَّد: تسجيل الدخول، الحصص، نظام التصميم، والمراقبة. ثم يدخل كل موديول من المسار B إلى المنصة **بعد اجتياز بوابته فقط**.

---

## 3. المراحل ومعايير القبول

### المرحلة صفر — تثبيت الأساس
مخرجات: مستودع منظم، مكونات تصميم مشتركة، نظام لغات من اليوم الأول، قاعدة بيانات ومصادقة وصلاحيات (RLS)، تخزين آمن ونسخ احتياطي **مُجرَّب**، تسجيل أخطاء ومراقبة، بيئات منفصلة (تطوير/اختبار/إنتاج)، توثيق التشغيل.

**معيار القبول:** إنشاء حساب تجريبي ← تطبيق صلاحياته ← استرجاع البيانات بعد اختبار استعادة نسخة احتياطية، **دون كشف أي مفتاح سرّي في المتصفح.**

### المرحلة الأولى — إصدار إسلامي أساسي
الصفحة الرئيسية والحساب والإعدادات · القرآن والبحث والعلامات · الأذكار والصلاة والقبلة والتقويم · مكتبة أولية بمصادر وحقوق واضحة · لوحة الإدارة · العربية والإنجليزية · PWA واختبارات الهاتف والكمبيوتر.

**معيار القبول:** مستخدم جديد يكمل رحلة حقيقية بالعربية أو الإنجليزية: عرض صحيح، حفظ تقدم، صلاحيات تعمل كما ينبغي.

### المرحلة الثانية — تجارب الصوتيات *(مسار B)*
قائمة مصادر مرشّحة وشروطها ← تشغيل فصل الصوت على ملفات مسموح بمعالجتها ← قياس الجودة ← قياس الزمن والتكلفة والتخزين ← اختبار الحذف التلقائي ← تجربة الحصة المجانية.

**معيار القبول:** جودة وفق مجموعة اختبارات محددة سلفًا + تكلفة معروفة + مصدر يسمح فعليًا. **لو لم يتوفر مصدر مرخص، لا يُطلق استيراد الأغاني من ذلك المصدر.**

### المرحلة الثالثة — تجربة YouTube وCreator Studio *(مسار B)*
مشروع تكامل ← ربط قناة يملكها الفريق ← قراءة البيانات المصرح بها ← اختبار رفع فيديو غير منشور ← قياس الحصص ← تصميم نموذج Agent ← اختبار الموافقات وإلغاء التفويض.

**معيار القبول:** الربط والقراءة والرفع تعمل ضمن الصلاحيات المعتمدة، وكل مهمة مسجّلة بحالتها، ولا يستطيع الوكيل تنفيذًا خارج تفويض المستخدم.

### المرحلة الرابعة — دمج أدوات الإنتاج
التحرير الأساسي للفيديو · التفريغ والترجمة والتصدير · حفظ المشاريع · مركز مهام موحّد · قوائم انتظار النشر والمعالجة · تقارير وحدود تشغيل الوكيل.
*(تُفتح فقط لوحدات اجتازت بوابتها.)*

### المرحلة الخامسة — التوسع العالمي
مصادر ومحتوى متعدد اللغات · الأكاديمية والمجتمعات والفعاليات · مصادر صوتية مرخصة إضافية عند توافرها · توسّعات Creator Studio والوكلاء · تحسين البحث والفهرسة والأداء · دراسة تطبيقات موبايل أصلية عند ظهور حاجة فعلية.

## 6. ما يبدأ الآن (ثلاثة مخرجات متوازية)

1. **وثيقة المتطلبات (PRD):** `docs/01-prd.md` ✅ (مسودة) — تُراجع عند كل تغيير حالة.
2. **خطة إثبات الجدوى:** `docs/02-poc-audio.md` + `docs/03-poc-youtube.md` ✅ — التنفيذان مستقلان.
3. **الأساس التقني:** هيكل المستودع + نموذج البيانات + الصلاحيات + الاختبارات — قيد التنفيذ.

**قاعدة مراجعة:** كل أسبوع تُحدَّث أعمدة "الحالة" في PRD وسجل المخاطر. ما لم يتغيّر قراره بالأرقام، يبقى `قيد التحقق`.
