# 09 — التخزين المحلي المؤقت (ملفات JSON)

> **الحالة:** مطبَّق ومُختبَر — التخزين الفعلي الحالي للتطوير.
> **المدة:** حتى أمر صريح بالتبديل إلى Supabase.
> **قاعدة ملزمة:** هذه بيانات **تجريبية**، لا تُعلن للمستخدمين كمحتوى معتمد.

---

## 1. لماذا JSON الآن؟

- لا يوجد مشروع Supabase بعد، وتعطيل العمل عليه غير مبرَّر.
- طبقة الوصول إلى البيانات (`src/lib/storage/`) معرَّفة بواجهة واحدة، فيمكن استبدال المزوّد دون لمس الصفحات.
- قواعد المحتوى (المصدر إلزامي، ولا نشر من مصدر غير موثّق) **مطبَّقة في المزوّد نفسه**، فلا تُكسر عند تغيير التخزين.

---

## 2. البنية

```
src/data/
  sources.json          سجل المصادر والرخص (نسخة JSON من جدول content_sources)
  quran-surahs.json     فهرس السور — بيانات وصفية فقط (مُجلَبة من الخارج)
  quran-text/           نص المصحف (الرسم العثماني) — ملف لكل سورة + _meta.json
  adhkar.json           عيّنة أذكار — كلها in_review
  library-items.json    عيّنات مكتبة تُظهر بوابة النشر
src/lib/storage/
  schemas.ts            مخططات zod + قواعد التحقق
  json.ts               مزوّد JSON (قراءة المحتوى + كتابة حالة المستخدم)
  index.ts              اختيار المزوّد (نقطة الوصول الوحيدة)
data/runtime/           حالة المستخدم (علامات القراءة) — غير مُتتبَّعة في git
```

### الواجهة

| الدالة | الوظيفة |
| --- | --- |
| `getContentStorage()` | محتوى للقراءة: مصادر، فهرس السور، أذكار، مكتبة |
| `getUserStorage()` | حالة المستخدم: علامات القراءة (إضافة/حذف/عرض) |

الصفحات تستهلك هذه الدوال فقط؛ لا تعرف من أين تأتي البيانات.

---

## 3. القواعد المطبَّقة عند التحميل

كل ملف يُفحص بـ zod عند أول قراءة، وأي خلل **يوقف الطلب برسالة واضحة** بدل عرض بيانات ناقصة:

1. **مخطط صالح:** الحقول المطلوبة، أنواع صحيحة، معرّفات فريدة.
2. **المصدر موجود:** كل قطعة محتوى (`sourceId`) تشير إلى مصدر معروف.
3. **بوابة النشر (P-4):** `status = published` ⇒ المصدر `verificationStatus = verified`.
4. **البيانات الوصفية ليست نصًّا:** فهرس السور لا يحتوي أي حقل نص قرآني.
5. **الأذكار التجريبية:** إسناد غير فارغ + حالة `in_review` (لا نشر قبل اللجنة الشرعية).

هذه القواعد مغطّاة باختبارات في `src/lib/storage/storage.test.ts`، منها اختبار يثبت **رفض** نشر قطعة من مصدر غير موثّق.

## 4. من أين جاءت البيانات؟

| الملف | المصدر | التحقق |
| --- | --- | --- |
| `quran-surahs.json` | [Al-Quran Cloud API](https://api.alquran.cloud/v1/surah) | يُجلب بـ `node scripts/fetch-quran-meta.mjs` مع تحقّقات تلقائية (114 سورة، تسلسل 1..114، عدد آيات 3..286) |
| `quran-text/` | [Tanzil](https://tanzil.net/download/) — `quranType=uthmani&outType=txt-2` | يُجلب بـ `node scripts/fetch-quran-text.mjs`: 6236 آية، مطابقة عدد كل سورة للفهرس، حفظ إشعار الحقوق، وبصمتا SHA-256 (للخام وللنص القانوني) |
| `sources.json` | نتائج تحقق `docs/04-content-sources.md` | رخصة + رابط رخصة + تاريخ تحقق لكل مصدر موثّق |
| `adhkar.json` | عيّنة تجريبية مكتوبة يدويًا | الموسوم `internal-demo` — **غير موثّق** ولا يُنشر |
| `library-items.json` | عيّنات إدارية | تُظهر بوضوح: منشور / مخطط / قيد المراجعة / بحاجة لفحص رخصة |

> **لا يُكتب نص قرآني من الذاكرة.** نص المصحف يُضاف فقط بعد ربط مصدر Tanzil واعتماد الإسناد، ويظل النسخ حرفيًا دون تعديل مع ذكر `tanzil.net`.

### 4.1 نص المصحف — ضمانات السلامة

- **حرفي بلا تعديل:** لا تطبيع ولا إعادة تشكيل ولا معالجة للنص؛ يُحفظ كل ما ورد من Tanzil.
- **بصمة مزدوجة:** `rawSha256` لباية الملف المنزَّل، و`canonicalSha256` للنص بعد فكّه إلى `sura|aya|text`. اختبار آلي يعيد بناء البصمة من الملفات المخزّنة ويقارنها — أي تغيير ولو حرفًا واحدًا يُفشل الاختبار.
- **مطابقة الفهرس:** عدد آيات كل سورة يُقارن بـ `quran-surahs.json` عند الجلب وعند كل قراءة.
- **إشعار الحقوق:** نص إشعار Tanzil محفوظ حرفيًا في `quran-text/_meta.json` (شرط الرخصة).
- **حالة المراجعة:** `reviewStatus = in_review` حتى قرار لجنة مكتمل. مخطط zod يرفض `approved` دون `reviewedBy` و`reviewedAt`، والاختبار يثبت أن الاعتماد لا يُدّعى بلا سجل.
- **تحديث النص:** `node scripts/fetch-quran-text.mjs` وحده؛ أي مصدر آخر مرفوض.

**عرض النص:** `/{locale}/quran/{surah}` — يعرض المصدر والرخصة وحالة المراجعة مع كل نص. البسملة تظهر كما في المصدر (مدمجة في الآية الأولى عدا الفاتحة والتوبة) ولا تُعاد صياغتها.

---

## 5. التبديل إلى Supabase لاحقًا

1. نفّذ `docs/08-supabase-setup.md` (إنشاء المشروع، `DATABASE_URL`، `npm run db:migrate`).
2. أضف مزوّد `postgres` يطبّق نفس دوال `ContentStorage`/`UserStorage` فوق `src/lib/db.ts`.
3. غيّر متغيّر البيئة فقط:
   ```env
   DATA_PROVIDER=postgres
   ```
4. شغّل `npm test` (تُضاف اختبارات RLS على قاعدة حقيقية عبر `TEST_DATABASE_URL`).

**لا تغيير مطلوب في الصفحات** — وهذا هو شرط قبول هذه الطبقة.

حاليًا `DATA_PROVIDER=postgres` يُعطي خطأً صريحًا (وليس فشلًا صامتًا) لأن المزوّد لم يُنفَّذ بعد.

---

## 6. حدود هذه المرحلة (معلنة صراحة)

- عرض المحتوى **تجريبي**: نص المصحف مستورد حرفيًا لكنه `in_review` حتى اعتماد اللجنة الشرعية.
- لا ترجمة ولا صوت ولا تفسير.
- حالة المستخدم محلية على القرص، بلا مصادقة ولا تعدد أجهزة.
- لا توجد صفحة أذكار بعد؛ البيانات موجودة ومُختبرة فقط.
